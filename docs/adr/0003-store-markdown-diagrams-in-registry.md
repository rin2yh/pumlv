# ADR 0003: Markdownの解析結果をRegistryのファイルエントリに保持する

## Context（背景）

PR #231 の図一覧をHTTPリクエストごとに全Markdownから解析すると、監視による差分更新の利点が失われる。また、図一覧と描画用ソースを別々に読み取ると、更新途中で行番号と図の内容が食い違いうる。

## Decision（決定）

初回登録とWatcherによる対象ファイルの更新時にMarkdownを解析し、図の行番号・タイトル・正規化済みソースをRegistryの同じファイルエントリに保持する。既存の排他制御と更新単位でエントリを置き換え、両APIはそのスナップショットを参照する。独立したキャッシュやHTTPリクエスト起点の再解析は追加しない。読み取り失敗時の登録維持・除外方針はADR 0001に従い、図の識別方法はADR 0002を維持する。

## Consequences（影響）

通常のファイル更新では対象Markdownだけを再解析し、削除時には解析結果も登録とともに破棄される。解析済みソースの保持にメモリを使い、監視イベントが反映されるまでは直前のスナップショットを返す。別々のAPIリクエストの間に更新が入ることはあるが、各エントリの図一覧とソースは一括で公開される。`.puml`などMarkdown以外のファイルは従来どおりリクエスト時に読み取る。
